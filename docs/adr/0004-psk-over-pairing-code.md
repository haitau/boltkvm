# ADR 0004：认证与密钥体系（预共享口令 + 静态密钥 + X25519 前向保密）

- 状态：已接受
- 日期：2026-10-23
- 相关：[README 快速开始](../../README.md)、[连接管理器设计](../plans/2026-10-22-connection-manager-design.md)

## 背景

两台 Mac 之间需要一套无需中心服务器、无需账号体系的认证与会话加密机制。备选方案有两种：

- **方案 P（持久预共享凭据 + 每会话临时密钥交换）**：被控端首次启动生成持久连接密码（或 256 位静态密钥）存入 `~/.boltkvm-key`，主控端在添加被控端时填入一次并按主机持久化；每次连接通过 HMAC-SHA256 挑战-应答完成认证，随后通过 X25519 交换临时公钥派生会话密钥。
- **方案 A（短效配对码换取长期密钥）**：被控端生成几分钟有效的短配对码，主控端输入配对码后在通道内交换 256 位随机密钥，配对码随即作废。

## 决策

采用 **方案 P**，不实现短效配对码换密钥（方案 A）：

1. **双形态预共享凭据**：
   - **8 位连接密码（默认）**：取自剔除易混淆字符（`0/o/1/l/i`）的 31 字符集（约 40 位熵），适合跨屏幕抄写；经 `PBKDF2-HMAC-SHA256`（12 万次迭代，固定盐 `boltkvm-psk-v1`）拉伸为 32 字节 PSK；
   - **256 位静态密钥（可选）**：被控端面板提供「256 位密钥…」按钮，生成 64 位十六进制随机字符串直接作为 32 字节 PSK（不拉伸），适合对离线穷举零容忍、可通过剪贴板传递的场景。
2. **X25519 前向保密（Forward Secrecy）**：
   - 挑战-应答认证（`authChallenge` → `authResponse` → `authOk`）通过后，先安装基于 `HKDF-SHA256(psk, salt=nonce)` 的初始加密层；
   - 若服务端在 `authOk` 标志位声明支持密钥交换（`FLAG_SUPPORTS_KEY_EXCHANGE`），双方立即通过加密通道交换 32 字节 X25519 临时公钥（`authExchange`，包类型 12），并将会话密钥升级为 `HKDF-SHA256(psk ‖ sharedSecret, salt=nonce)`。

## 理由

1. **在线与离线穷举均已被阻断**：
   - 在线认证失败后服务端强制延迟 1 秒并断开，40 位口令无法在线穷举；
   - PBKDF2 12 万次迭代将单次离线猜测成本拉高数万倍；配合 X25519 前向保密，即使攻击者录下握手与会话密文，事后拿到口令也无法解密历史流量；对 40 位熵仍有顾虑的用户可直接切换 256 位静态密钥。
2. **方案 A（短配对码）的简化实现反而更脆弱**：
   - 若直接把 6–8 位短配对码当临时密钥加密传输长期密钥，攻击者只需录下配对过程即可离线穷举短码并拿到长期密钥；
   - 若要安全实现短码配对，必须引入 PAKE（如 SPAKE2 / OPAQUE），而 Apple CryptoKit 未内置 PAKE，手写密码学协议风险极高且维护成本不对称。
3. **操作体验更直接**：
   - 持久连接密码无过期时间限制，被控端生成后主控端只需填写一次；需要吊销时在被控端面板点击「重新生成密码…」即可使所有旧客户端失效。

## 后果

- 连接密码需通过带外方式（看屏幕手输或复制粘贴）传递一次，两端可通过比对 16 位十六进制指纹（SHA-256 前 8 字节）确认凭据一致；
- 常规会话具备完整前向保密；`--insecure` 仅作为显式调试逃生口保留（启动时打印明文警告）；
- 重新生成密码会使所有已保存该主机的客户端同时失效，不支持单台客户端独立吊销。
