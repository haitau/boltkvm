# 客户端连接管理（多被控端）：需求与设计

- 状态：R1 / R2 / R4 / R5 已实现并验证；R3 受系统安全边界限制暂不实现（2026-10-23）
- 关联：[连接管理器实现与协议细节](2026-10-22-connection-manager-design.md)

## 1. 背景与目标

早期客户端为单一视频窗口加顶部连接栏，每次只能手填一台被控端的 `主机 / 端口 / 密钥`，且分辨率只能在服务端启动参数中固定。为对齐 macOS 系统「屏幕共享」的使用体验，连接管理器拆分为以下五项需求：

| 编号 | 需求 | 状态 |
|---|---|---|
| **R1** | 启动主界面改为被控端列表，支持多台被控端的增删改与双击连接 | **已完成** |
| **R2** | 每台被控端可独立配置分辨率，连接时动态通知服务端调整虚拟屏尺寸 | **已完成** |
| **R3** | 保存远端 macOS 账户登录密码并在锁屏界面自动解锁 | **暂不实现（受系统权限限制）** |
| **R4** | 移除冗余的「断开」按钮，关闭视频窗口即断开连接并返回主机列表 | **已完成** |
| **R5** | 将 `fps · Mbps` 实时传输状态移至工具栏最右侧显示 | **已完成** |

## 2. 凭据存储策略

客户端涉及两类不同性质的凭据，存储策略如下：

| 凭据类型 | 用途 | 存储位置与权限 | 说明 |
|---|---|---|---|
| **连接密码 / PSK** | 传输层挑战-应答认证与派生会话密钥 | `~/Library/Application Support/BoltKVM/keys/<host>_<port>`（权限 `0600`） | 按主机独立保存，`hosts.json` 中仅存文件名引用（`pskAccount`），不存密码明文 |
| **远端系统登录密码（R3）** | 解锁被控端 macOS 登录窗口 / 锁屏 | 暂不收集 | 服务端处于 `loginwindow` Secure Input 状态时，普通用户态进程无法注入解锁按键；在具备 root 特权 helper 前不收集系统登录密码 |

**为什么不存储在 macOS 钥匙串（Keychain）**：
本项目通过开源源码或无公证 Release 分发，每次重编译或版本更新都会改变二进制签名哈希，导致 macOS Keychain 将其识别为不同程序并弹出「BoltKVM 想使用您储存在钥匙串中的机密信息」模态授权框，阻塞连接流程。采用应用数据目录下的 `0600` 权限文件（与 `~/.boltkvm-key` 安全级别一致），既避免明文混入配置 JSON，又消除了重签名后的弹窗干扰。

## 3. 验收标准与实测结果

1. **冷启动列表（R1）**：启动直接展示被控端列表窗口（自动迁移旧版 `Prefs.host/port` 配置），支持新建、编辑、删除与双击连接；
2. **按主机分辨率（R2）**：在编辑面板修改目标分辨率并保存，重连后客户端发送 `config` 包，服务端自动按新尺寸重建虚拟屏；
3. **关窗即断开（R4）**：移除「断开」按钮；关闭视频窗口后服务端立即记录 `client disconnected` 并停止编码，客户端自动退回主机列表窗口；
4. **工具栏状态（R5）**：工具栏最右侧每秒刷新显示 `fps · Mbps`；
5. **凭据隔离**：连接密码保存在 `keys/` 目录下（权限 `0600`），`hosts.json` 与日志中均不包含密码明文。
