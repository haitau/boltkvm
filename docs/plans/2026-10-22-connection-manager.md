# 客户端连接管理（多被控端）· 需求记录

> 2026-10-22 由用户提出，对标 macOS 屏幕共享（"所有连接"界面）。本文只记录**需求与约束**，不含实现方案；实现前先在这里补方案与协议改动。

## 现状

- 客户端是一个窗口 + 一条连接栏，手填 `主机 / 端口 / 密钥`，**一对一**；
- 断开靠连接栏上的「断开」按钮；
- 分辨率、清晰度是**服务端启动参数**（`--width/--height` 决定虚拟显示尺寸，画质是编码参数），客户端无法按连接配置。

## 需求

### R1 启动界面 = 被控端列表

应用启动后的主界面改成"所有连接"式的列表/卡片：每台被控端一张卡片（名称、图标、上次连接时间），支持新建。

- 现在是一对一；**目标是 1:N**（多台被控端，以后可能同时开多个会话）；
- 对标截图还包含左侧「所有连接 / 网络」分组与顶部视图切换（网格/列表），可作为后续增强。

### R2 每台被控端可编辑，编辑内容含分辨率与清晰度

点卡片上的「编辑」进入配置面板，字段至少包括：名称、服务器地址、用户名、端口、屏幕共享类型、**分辨率**、**清晰度**；保存后对该被控端持久生效。

> 技术前提：这需要协议扩展。目前客户端在连接时只能传地址/端口/PSK，分辨率与画质由服务端启动参数决定。要支持"每台被控端配置"，需要客户端在登录后下发 desired config（或 auth 包携带），服务端据此创建虚拟显示与编码器。

### R3 保存远端锁屏界面时的登录密码

对标 macOS 屏幕共享：记住被控端登录界面（锁屏/登录窗口）的密码，用于解锁。

> 技术前提：当前只有虚拟显示上的普通桌面会话，没有登录窗口/解锁注入能力，这一项依赖服务端新增能力。存储必须走 Keychain，不能明文落盘。

### R4 去掉「断开」按钮

「断开」没有必要，等价于窗口的系统关闭按钮（左上角红灯）：**关闭窗口即断开**。

### R5 实时连接信息移到工具栏最右侧

`fps · Mbps` 这类实时状态从连接栏移到工具栏最右边显示，不再占用连接栏。

## 验收标准（可测）

1. 冷启动直接看到被控端列表，没有连接栏；双击卡片即连接；
2. 编辑面板能改分辨率/清晰度并持久化，重连后服务端日志可见新尺寸生效；
3. 关闭窗口后，服务端日志出现 `client disconnected`，且不再编码；
4. 窗口内不存在「断开」按钮；
5. 工具栏最右侧显示 `fps · Mbps`，约 1 秒刷新；
6. 保存的密码在 Keychain 中（`security find-generic-password -s boltkvm` 可查到条目），全盘 grep 不到明文。

## R3 补充：两个都存，但分开存（2026-10-22 定）

判断依据：这是两种**完全不同**的凭据，不能混在一条记录里，默认策略也不同。

| 凭据 | 用途 | 默认是否保存 | Keychain 条目 | 理由 |
|---|---|---|---|---|
| PSK（`~/.boltkvm-key`） | 传输层认证：连接握手时证明"我是授权客户端" | **保存** | `keys/<host>_<port>`（0600 文件） | 1:N 之后每台被控端可能不同；不存就得每次手贴，等于把多主机功能废掉 |
| 远端登录密码 | 连接建立**之后**，解锁被控端的锁屏/登录界面 | **不保存**，需在编辑面板勾选"记住登录密码" | `boltkvm-login` / `<user>@<host>` | 这是用户账号密码，风险级别更高；且依赖服务端登录注入能力，能力上线前不应收集 |

约束：

- 连接配置（JSON/UserDefaults）里**只存 Keychain 引用**（`keychainRef`），不存明文；
- 密码不写日志、不写诊断包、不进崩溃报告；
- 重签名会让 Keychain 的 ACL 失效，已有条目需要重新授权/重新输入一次——和"本地网络权限被重置"是同一类坑，实施时在已知问题里登记。
