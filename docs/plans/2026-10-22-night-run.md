## 目标

1. 让工具栏三个动作（App / 调度中心 / 桌面）**全部可用**，且不依赖 TCC 自动化授权（B1）；
2. 定位并修掉**客户端窗口消失**（B2）；
3. 观察并记录 B3（首次连接偶发）、B4（右上角黑三角）；
4. R4：去掉「断开」按钮，关窗即断开；
5. R5：`fps · Mbps` 移到工具栏最右侧；
6. 时间允许则做 R1（启动界面改为被控端列表）；
7. 启动并完成 **8 小时输入连续性** 测试，顺带复核 >10 分钟稳定性。

## 阶段与顺序

| 阶段 | 内容 | 验收方式 |
|---|---|---|
| P1 | B1：三个动作改为服务端 CGEvent 注入（与输入转发同一路径），删除 AppleScript 依赖 | 在客户端点按钮后截图远端画面，逐个确认 App Exposé / 调度中心 / 桌面 生效；服务端日志无 -1743 |
| P2 | B2：给 `windowWillClose` / `shutdown()` 打点（含调用栈），复现后按调用栈修 | 复现脚本：连接→断开→重连 ×5，窗口不再消失；日志能解释历史现象 |
| P3 | R4：移除「断开」按钮；关窗 = 断开 | 点窗口红灯后服务端日志出现断开、停止编码；重开窗口可再连 |
| P4 | R5：状态标签移到工具栏最右侧 | 截图确认位置；状态每秒刷新 |
| P5 | B3 / B4：各做一轮针对性观察，能修则修，不能修则写清复现条件 | 报告里给出结论与证据 |
| P6 | R1：连接列表（能到哪算哪） | 冷启动见列表、可新增/删除、双击连接 |
| P7 | 8 小时输入连续性 + >10 分钟稳定性 | `scripts/input-continuity.sh` 跑满 8h，出报告 |

> 8 小时测试会持续注入输入，会干扰 UI 截图验证，所以放在最后启动。

- 部署到 mini 的流程沿用：build-app → tar → scp → 替换 → open；每次部署后确认客户端能连上；
- 所有结论写进 `docs/reports/2026-10-22-night-run.md`，包括失败的尝试；

## 风险与应对

- **mini 只有一台**：改坏了就从 `dist/BoltKVM.app` 重新部署；服务端崩溃时 ssh 拉起来；
- **8h 测试可能因网络/休眠中断**：脚本自身有重连，中断就记录中断点并重跑；
- **时间不够**：P6（R1）可裁剪，P1–P5 必须完成。
